🛡️ AWS Security Weekly Radar
Week of 2026-09-30 to 2026-10-07
A heavy week for AI tooling CVEs, plus practical wins in detection: GuardDuty by organization policy and grouped remediation in Security Hub.
This week's highlights
🟠 NEWS AWS Security Hub introduces remediation plans to prioritize and fix security exposures (2026-10-01)
Why it matters: Remediation plans group exposure findings by root cause, so one fix can close several exposures. Each plan comes with step-by-step guidance in CLI, Terraform, CloudFormation and CDK.
Suggested action: Use the critical and high plans as next sprint's backlog and keep the fixes in IaC.
🟠 NEWS Amazon GuardDuty now supports centralized management using AWS Organizations declarative policies (2026-10-01)
Why it matters: GuardDuty can now be enabled through an AWS Organizations declarative policy, which covers existing accounts and every new one without custom automation.
Suggested action: Replace enablement scripts with the declarative policy and check coverage per account and Region.
🟠 NEWS GuardDuty Runtime Monitoring is now included in the AWS Security Hub Threat Analytics plan (2026-10-02)
Why it matters: Runtime Monitoring is now part of the Security Hub Threat Analytics plan, with no separate GuardDuty charge where Security Hub is on.
Suggested action: Review runtime coverage for EC2, EKS and Fargate and remove duplicate billing.
🟠 NEWS AWS Continuum for Penetration Testing now supports continuous penetration testing integrated directly into your CI/CD pipeline (2026-10-05)
Why it matters: AWS Continuum can run penetration tests inside CI/CD pipelines (public preview), moving testing from yearly to every change.
Suggested action: Pilot it on a non-critical repository and compare findings with your last external pentest.
